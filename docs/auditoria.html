6. Checklist Final de Validación para GitHub Pages (Desktop y Mobile)

Ejecuta y registra lo siguiente después de subir el código. No marques el capítulo como 100% cumplido solo porque la página abre.

  1. Crear el repositorio y subir el contenido interior del ZIP. Verificar las cinco carpetas oficiales, favicon, .gitignore y .nojekyll; no subir solo el archivo ZIP.
  2. Elegir Settings → Pages → Deploy from a branch → main → /(root). Esperar el despliegue correcto en Actions y guardar URL/commit.
  3. Abrir la URL pública raíz y comprobar que llegue a /pages/index.html. Abrir esta ruta directamente en otra pestaña o ventana privada.
  4. Comprobar estilos, Inter, favicon, imágenes y JS sin errores de carga. Verificar mayúsculas exactas y ausencia de rutas locales o con / inicial hacia el dominio.
  5. Iniciar sin datos y verificar sin perfil, sin coordenadas y Buscando señales. Cargar los casos ficticios y comprobar las tres categorías de atención.
  6. Registrar un perfil ficticio: intentar enviar vacío, edad decimal y 201 caracteres de instrucciones. Cada error debe indicar el campo y llevar el foco al primero.
  7. Guardar edad 0 o un entero válido, sangre conocida o Desconocido, alergia explícita o ausencia conocida, varias condiciones o ninguna conocida e instrucciones o No aplica. Recargar y comparar valores.
  8. Modificar sin guardar; intentar cambiar de rol, descartar o cerrar pestaña. Cancelar debe conservar el borrador y confirmar debe tener el efecto informado.
  9. Guardar sin autorización y activar SOS: el rol Rescatista recibe señal básica sin nombre ni salud. Autorizar y guardar; comprobar perfil. Revocar y confirmar que deja de verse.
  10. Provocar fallo SOS y reintentar. Cambiar el perfil durante el fallo para comprobar que se conserva el paquete del intento; una revocación sí debe retirar datos médicos.
  11. Probar una transcripción errónea y la frase exacta. La errónea no activa; la exacta cambia el estado local. Registrar explícitamente que esto no acredita voz por audio.
